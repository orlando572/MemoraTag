# Plan de trabajo

## Equipo y plazo

El proyecto se desarrollará entre dos integrantes durante un plazo estimado de tres a cuatro semanas. Se priorizará el flujo móvil que será evaluado y se reservará tiempo para las pruebas presenciales y el artículo.

## Distribución de tareas

Ambos integrantes trabajarán en frontend y backend mediante funcionalidades completas, en lugar de dividirse permanentemente por capas. La asignación es flexible y puede ajustarse según el avance y las dificultades.

| Periodo | Integrante 1 | Integrante 2 |
|---|---|---|
| Semana 1 | Base móvil, almacenamiento local y prueba NFC. | Base de backend y web, Supabase y prueba de autenticación. |
| Semana 2 | Objetos: pantallas móviles, persistencia y endpoints. | Eventos: pantallas móviles, persistencia y endpoints. |
| Semana 3 | QR/NFC y consulta pública: integración móvil, resolución y vista web. | Archivos y sincronización: selección, almacenamiento y operaciones de backend. |
| Semana 4 | Correcciones, pruebas de sus flujos y apoyo a la evaluación. | Correcciones, pruebas de sus flujos y apoyo a la evaluación. |
| Durante todo el proyecto | Revisión, integración y artículo. | Revisión, integración y artículo. |

Ambos diseñarán y probarán la sincronización, ya que conecta objetos, eventos y archivos. También participarán en la evaluación presencial y el análisis de resultados.

## Forma de trabajo

- Definir juntos los contratos de datos y API antes de implementar cada funcionalidad.
- Utilizar ramas cortas y revisar los cambios del compañero.
- Integrar frecuentemente móvil, web y backend.
- Mantener un tablero sencillo de tareas, responsables y bloqueos.
- Realizar pruebas internas durante todo el desarrollo.

## Hitos

1. **Semana 1:** entorno base y lectura y escritura NFC comprobadas; protocolo de evaluación preparado.
2. **Semana 2:** flujo principal de objetos y eventos funcionando localmente y operaciones básicas en la nube.
3. **Semana 3:** versión integrada con sincronización, archivos y web básica, lista para pruebas internas.
4. **Semana 4:** correcciones, evaluación presencial con SUS y resultados preparados para el artículo.

## Prioridades y riesgos

Comprobar NFC al inicio y priorizar el flujo móvil y offline: crear un objeto, identificarlo, consultar su historia y registrar eventos. La cuenta, sincronización y privacidad deben integrarse sin ampliar la web hacia un panel empresarial avanzado.

Los principales riesgos son el plazo, la integración NFC, los conflictos y duplicados en sincronización, la gestión segura de archivos y la disponibilidad de participantes. Es importante reservar tiempo para la evaluación, no dejarla para después del desarrollo.

Si solo se dispone de tres semanas, se adelantará la evaluación y se reducirá el alcance no esencial de la web y los detalles secundarios, manteniendo los requisitos centrales acordados.
